## READ
1. Berkas mana yang menangani POST login? Method apa?
   Jawab: route `POST /login` ada di `routes/auth.php` dan mengarah ke method `store()` di `AuthenticatedSessionController.php`, di method ini data login yang dimasukkan pengguna diproses untuk ngecek apakah email dan passwordnya benar

2. Di baris mana `Auth::attempt()` atau setaranya dipanggil?
   Jawab: `Auth::attempt()` ada di method `authenticate()` di `LoginRequest.php`, tepatnya baris 45. di `AuthenticatedSessionController.php`, method `store()` memanggil `$request->authenticate()`. jadi, proses pengecekan email dan password ada di `LoginRequest.php` lalu dipanggil pas pengguna mencoba login

3. Temukan `session()->regenerate()`. Kenapa ia ada di situ?
   Jawab: `session()->regenerate()` ada di method `store()` di `AuthenticatedSessionController.php` baris 29, kode ini dijalankan setelah login berhasil untuk mengganti ID session pengguna. tujuannya supaya ID session yang dipakai sebelum login ga terus dipakai setelah berhasil login, jadi bisa membantu mencegah session fixation

4. Di mana kata sandi di-hash?
   Jawab: pengaturan hashing password ada di method `casts()` di `User.php`, yaitu `'password' => 'hashed'`. jadi, pas password disimpan lewat model, password bakal otomatis dihash dan ga disimpan sebagai teks biasa di database. hash juga tidak bisa dikembalikan gitu saja ke password aslinya, makannya kalau lupa password pengguna perlu melakukan reset password

5. Buka DevTools → Cookies sebelum dan sesudah login. Bandingkan nilai cookie session.
   Jawab: saya buka inspect element dengan menekan F12, lalu masuk ke menu Application → Cookies dan pilih domain web KampusLMS. sebelum login, cookie session punya nilai teks acak. setelah berhasil login, nilai cookie tsb berubah jadi teks acak yang beda. dari situ saya bisa melihat adanya perubahan cookie session setelah login. hal ini sesuai dengan fungsi `session()->regenerate()` yang mengganti ID session setelah login berhasil untuk membantu mencegah session fixation

6. Logout, lalu tekan tombol back. Apa yang terjadi? Kenapa?
   Jawab: setelah logout lalu menekan tombol back, halaman sebelumnya mungkin masih terlihat karena tersimpan di cache browser. tapi pas halaman yang membutuhkan login dibuka atau dimuat ulang, pengguna seharusnya diminta login lagi karena session sebelumnya sudah diakhiri. proses logout ada di method `destroy()` pada `AuthenticatedSessionController.php`, disitu session dihapus dan token session diperbarui supaya sesi sebelumnya tidak bisa dipakai lagi
